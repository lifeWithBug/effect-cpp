## 一、为什么需要图

树处理的是 **一对多** 的层次关系（文件夹→子文件夹），但现实中的关系往往是 **多对多**：

- 社交网络：A 认识 B，B 认识 C，C 认识 A
- 交通路网：城市之间没有上下级，任意两个都可能直连
- 互联网拓扑：路由器之间互相连接形成网状

**图** 是比树更一般的数据结构——允许环、允许多种连通方式。树是图的特例（连通无环）。

## 二、核心术语

```
     0 ------ 1
     |      / |
     |     /  |
     |    /   |
     2 ------ 3 ------ 4
```

| 术语 | 含义 | 举例 |
|------|------|------|
| 顶点（Vertex） | 图中的结点 | 0, 1, 2, 3, 4 |
| 边（Edge） | 顶点之间的连线 | (0,1), (1,3), (3,4) |
| 无向图 | 边无方向，(u,v)=(v,u) | 上图 |
| 有向图 | 边有方向，u→v 和 v→u 不同 | 微博关注 |
| 邻接（Adjacent） | 边直接相连的两个顶点 | 0 和 2 邻接 |
| 度（Degree） | 与顶点相连的边数 | 顶点 1 的度为 3 |
| 入度 / 出度 | 指向顶点的边 / 从顶点出发的边 | 有向图 |
| 路径（Path） | 顶点序列，相邻有边 | 0→1→3→4 |
| 连通 | 任意两点间有路径 | 上图连通 |
| 连通分量 | 极大连通子图 | 遍历算法中出现 |
| 完全图 | 每对顶点间都有边 | n 个顶点有 n(n-1)/2 条边 |
| 权（Weight） | 边上的数值 | 地图导航的核心 |
| 子图 | 顶点子集 + 边子集构成的图 | 取 {0,1,2} 和其间边 |
| 生成树 | n 个顶点的连通子图，n-1 条边 | 连通图必有生成树 |
| 简单图 | 无自环、无重边 | 默认讨论的都是简单图 |

## 三、图的存储方式

### 3.1 邻接矩阵

```c
int mat[MAXV][MAXV];  // mat[u][v] = 1 表示 u→v 有边
```

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 判断 u,v 是否有边 | O(1) | 直接读 `mat[u][v]` |
| 找 v 的所有邻居 | O(n) | 必须遍历整行 |
| 空间 | O(n²) | n=10⁵ 时存不下 |
| 适用 | 稠密图（边数≈n²） | 各种算法题的默认结构 |

无向图中，第 i 行所有 1 的个数 = 顶点 i 的度。
有向图中，第 i 行之和 = 出度，第 j 列之和 = 入度。

### 3.2 邻接表

```c
// 顶点 0 挂的链表: 1 → 2 → NULL
// 顶点 1 挂的链表: 0 → 2 → 3 → NULL
typedef struct EdgeNode {
    int adjvex;
    struct EdgeNode *next;
} EdgeNode;
typedef struct {
    EdgeNode *first;  // 链表的头指针
    int data;
} VertexNode;
```

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 找 v 的所有邻居 | O(deg(v)) | 遍历链表 |
| 判断 u,v 有边 | O(deg(u)) | 需遍历链表 |
| 空间 | O(n+e) | 稀疏图（e<<n²）最优 |
| 适用 | 稀疏图、大型图 | 工程实现 |

### 3.3 选择口诀

```
边多 → 邻接矩阵（稠密图）
边少 → 邻接表（稀疏图）
考试 → 邻接矩阵（好写、不易错）
```

完整代码见 [./graph_basics.c](./graph_basics.c)。

## 四、图的基本性质

**性质 1：握手定理**

无向图：**∑度 = 2e**。每条边贡献 2 度。推论：拥有奇数个的度的顶点一定有偶数个。

**性质 2：有向图的度**

∑入度 = ∑出度 = e。

**性质 3：连通性下界**

n 个顶点的连通图至少有 n-1 条边。恰好 n-1 条时就是树。

**性质 4：生成树**

连通图包含所有顶点、n-1 条边的连通子图。任何连通图至少有一棵生成树。最小生成树（MST）问题由此而来。

## 五、图的分类全景图

```
图
├── 按方向
│   ├── 无向图（边双向）
│   └── 有向图（边有方向）→ 入度/出度
├── 按边权
│   ├── 无权图
│   └── 带权图（网络）→ 最短路径
├── 按连通性
│   ├── 连通图/强连通图
│   └── 非连通图 → 连通分量
├── 按密度
│   ├── 稠密图（e≈n²）
│   └── 稀疏图（e<<n²）
├── 按特殊结构
│   ├── 完全图（每对顶点都有边）
│   ├── 树（连通无环）→ 图的特例
│   ├── 有向无环图（DAG）→ 拓扑排序
│   ├── 二分图 → 匹配问题
│   └── 欧拉图/哈密顿图
└── 带环图 → 有环≠有问题，恰恰是图的常态
```

## 六、图的遍历

### 6.1 与树遍历的本质区别

树的遍历不需要标记已访问——树无环。图的遍历必须用 **visited 数组**：

```
树遍历：               图遍历：
preOrder(node):        dfs(v):
    if node==NULL         visited[v]=true
        return            for each neighbor u:
    visit(node)               if !visited[u]: dfs(u)
    preOrder(left)
    preOrder(right)
```

差的就是这一行 `visited`。少了它，图遍历必死循环。

### 6.2 深度优先搜索（DFS Depth-First-Search）

**核心**：一条路走到黑，没路了再回头。

```c
void dfs(Graph *g, int v, int visited[]) {
    visited[v] = 1;
    visit(v);                     // 前序位置（输出）
    for (每个邻居 u)
        if (!visited[u])
            dfs(g, u, visited);
}
```

**应用 1：连通分量**

```c
int count = 0;
for (int v = 0; v < n; v++)
    if (!visited[v]) {
        count++;
        dfs(g, v, visited);
    }
```

对整个图调一次 DFS 覆盖一个连通分量，调用次数就是分量数。

**应用 2：无向图环检测**

```c
int hasCycle(int v, int parent) {
    visited[v] = 1;
    for (每个邻居 u) {
        if (!visited[u]) {
            if (hasCycle(u, v)) return 1;
        } else if (u != parent) {
            return 1;  // 发现回边 → 有环
        }
    }
    return 0;
}
```

### 6.3 广度优先搜索（BFS Breadth-First Search）

**核心**：一圈一圈往外扩。用队列实现。

```c
void bfs(Graph *g, int start) {
    visited[start] = 1;  enQueue(q, start);
    while (队列不空) {
        v = deQueue(q);  visit(v);
        for (每个邻居 u)
            if (!visited[u]) {
                visited[u] = 1;  // 入队即标记！
                enQueue(q, u);
            }
    }
}
```

> **重要**：在入队时标记 visited（而不是出队时），防止同一顶点的邻居重复入队。

**BFS 的特性**：第一次访问一个顶点时，走过的路径一定是最短的（无权图单源最短路径）。

### 6.4 DFS vs BFS

| | DFS | BFS |
|--|-----|-----|
| 工具 | 栈（递归） | 队列 |
| 空间 | O(h)，h 为递归深度 | O(w)，w 为最大宽度 |
| 可求 | 连通分量、环、回溯路径 | 无权图最短路径 |
| 记忆 | 一条路走到黑 | 一层层向外扩 |

**完整代码**见 [./graph_traversal.c](./graph_traversal.c)。

## 七、最小生成树

**生成树** = 包含所有 n 个顶点、恰好 n-1 条边、保持连通。

**最小生成树（MST）** = 所有生成树中边权和最小的。

### 7.1 Prim 普利姆算法

**思想**：从一个顶点开始，每次选"已选集合到未选集合"的最小边，拉入新顶点。

```c
prim(graph, n, start):
    初始化：selected[start]=1, minDist[i]=graph[start][i]
    重复 n-1 次：
        取 minDist 最小的未选顶点 u
        selected[u]=1
        更新 minDist: minDist[v]=min(minDist[v], graph[u][v])
```

关键区别（对比 Dijkstra）：

| | Prim | Dijkstra |
|--|------|----------|
| minDist 含义 | 到已选集合的最小边权 | 到源点的累计距离 |
| 更新方式 | `min(dist, w(u,v))` | `min(dist, dist[u]+w(u,v))` |

时间复杂度：O(n²)（朴素），O(e log n)（堆优化）

**适用**：稠密图。

### 7.2 Kruskal 克鲁斯卡尔算法

**思想**：把边按权值从小到大排序，只要不产生环就加入。

```c
kruskal(edges, en, n):
    按权值排序 edges
    初始化并查集
    for each edge (u,v,w) 从小到大:
        if find(u) != find(v):
            加入此边: union(u,v)
```

**并查集（Union-Find）** 是 Kruskal 的灵魂：

```c
int find(int x) {                // 找根 + 路径压缩
    while (parent[x] >= 0) x = parent[x];
    return x;
}
void unionSet(int a, int b) {    // 按秩合并
    int ra = find(a), rb = find(b);
    if (parent[ra] < parent[rb]) { parent[ra] += parent[rb]; parent[rb] = ra; }
    else { parent[rb] += parent[ra]; parent[ra] = rb; }
}
```

时间复杂度：**O(e log e)**（排序主导）

**适用**：稀疏图。

### 7.3 Prim vs Kruskal

| | Prim | Kruskal |
|--|------|---------|
| 策略 | 从顶点扩展 | 从边归并 |
| 核心结构 | minDist 数组（优先队列） | 并查集 |
| 时间复杂度 | O(n²) | O(e log e) |
| 适用 | 稠密图（边多） | 稀疏图（边少） |
| 证明依据 | 割性质 | 环性质 |

**完整代码**见 [./graph_mst.c](./graph_mst.c)。
