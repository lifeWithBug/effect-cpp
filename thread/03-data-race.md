# C++ 多线程笔记 03：数据竞争与竞态条件

## 1. 先看一个经典问题

```cpp
#include <iostream>
#include <thread>

int counter = 0;           // 共享全局变量

void increment() {
    for (int i = 0; i < 100000; ++i) {
        ++counter;          // 看似一行，实则三步
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);
    t1.join();
    t2.join();
    std::cout << counter << "\n";  // 期望 200000
    return 0;
}
```

**实际运行结果**：每次都不一样，通常远小于 200000。为什么？

## 2. counter++ 在 CPU 层面是三条指令

```
load  counter  → 寄存器    // 1. 从内存读
add   寄存器 +1            // 2. 加 1
store counter ← 寄存器    // 3. 写回内存
```

两个线程交错时可能发生：

```
时间 →→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→
线程1: load(0) → add(1)                       store(1)
线程2:              load(0) → add(1) → store(1)
```

两次 `++`，最终结果是 1 而不是 2。这叫**数据竞争 (data race)**。

## 3. 数据竞争的定义

C++ 标准对数据竞争的定义：

> 两个线程同时访问同一内存位置，**至少一个是写操作**，且没有同步措施 → **未定义行为**

核心要素：
1. **两个以上线程**
2. **同一内存位置**
3. **至少一个写操作**
4. **没有同步**（没有锁、原子操作等）

## 4. 未定义行为意味着什么？

不是"结果可能不对"，而是**可能发生任何事**：
- 结果和预期不符
- 程序崩溃（segfault）
- 死循环
- 破坏其他无关变量的值
- 在不同平台上表现不同

```cpp
// 更真实的问题：不仅仅是记数不准
bool ready = false;
int data = 0;

// 线程 A
data = 42;
ready = true;

// 线程 B
while (!ready);      // 可能永远循环（编译器的优化？CPU 重排？）
std::cout << data;   // data 可能还是 0
```

## 5. 竞态条件 (Race Condition)  vs  数据竞争 (Data Race)

容易混淆的两个概念：

| | 数据竞争 | 竞态条件 |
|------|----------|----------|
| **本质** | 硬件/语言层面的问题，无同步的并发访问 | 逻辑层面的问题，程序结果取决于执行顺序 |
| **是否 UB** | 是，未定义行为 | 不一定，可能只是逻辑错误 |
| **例子** | 两个线程同时写同一个变量 | 先检查余额再扣款，中间被其他线程修改了 |

**关系**：数据竞争通常导致竞态条件，但有竞态条件不一定有数据竞争（如果用了锁但逻辑本身有问题）。

## 6. 临界区 (Critical Section)

**临界区**：必须互斥执行的代码段——同一时间只有一个线程可以进入。

```
线程 A: [其他工作] → [████ 临界区 ████] → [其他工作]
线程 B: [其他工作] → [████ 等待中 ████] → [████ 临界区 ████]
```

保护临界区的工具就是下一节要讲的 **mutex（互斥量）**。

## 7. 如何避免数据竞争？

| 方法 | 说明 |
|------|------|
| **互斥锁 (mutex)** | 保护临界区，同一时间只允许一个线程进入 |
| **原子操作 (atomic)** | 对简单变量的读写保证原子性 |
| **无共享** | 各线程操作自己的数据，不共享 |
| **只读共享** | 如果只有读操作，不需要同步 |
