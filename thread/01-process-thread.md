# C++ 多线程笔记 01：进程与线程

## 1. 进程 (Process)

进程是操作系统**资源分配**的基本单位。每个进程拥有：

- **独立的地址空间**：进程 A 无法直接访问进程 B 的内存
- **独立的资源表**：文件描述符、句柄、环境变量
- **至少一个线程**（主线程）
- **独立的页表、信号处理、打开的文件等**

一个进程的内存布局：

```
┌──────────────────────────┐  ← 高地址
│        栈 (Stack)         │  局部变量、函数调用帧
├──────────────────────────┤
│          ↓ 增长           │
│                          │
│          ↑ 增长           │
├──────────────────────────┤
│        堆 (Heap)          │  new/malloc 分配的内存
├──────────────────────────┤
│    全局/静态区 (BSS+Data) │  全局变量、static 变量
├──────────────────────────┤
│     代码段 (Text)         │  编译后的机器指令
└──────────────────────────┘  ← 低地址
```

## 2. 线程 (Thread)

线程是 **CPU 调度**的基本单位。同一进程内的线程共享进程的资源，但有自己独立的部分。

### 线程共享的部分
```
┌──────────────────────────────┐
│         进程地址空间           │
│  ┌──────┐  ┌──────┐  ┌──────┐ │
│  │线程 A │  │线程 B │  │线程 C │ │
│  │ (栈)  │  │ (栈)  │  │ (栈)  │ │  ← 每个线程独立
│  ├──────┤  ├──────┤  ├──────┤ │
│  │     寄存器上下文     │      │ │  ← 每个线程独立
│  ├──────┴──────┴──────┤ │
│  │                    │ │
│  │  共享：堆 / 全局 / 代码  │ ← 所有线程共享
│  │                    │ │
│  └────────────────────┘ │
└──────────────────────────────┘
```

### 共享 vs 独立

| 资源 | 是否共享 | 说明 |
|------|---------|------|
| 地址空间 | ✅ 共享 | 一个线程的指针可以直接访问另一个线程的变量 |
| 全局变量 | ✅ 共享 | 全局/静态变量对所有线程可见 |
| 堆 (new/malloc) | ✅ 共享 | 一个线程分配，另一个线程可以释放 |
| 文件描述符 | ✅ 共享 | 一个线程 open，另一个可以 read |
| 信号处理 | ✅ 共享 | 对信号的响应全局统一 |
| **栈** | ❌ 独立 | 每个线程有自己的栈空间 |
| **寄存器** | ❌ 独立 | 包括 PC、SP、通用寄存器 |
| **线程 ID** | ❌ 独立 | `std::this_thread::get_id()` |
| **errno/tls** | ❌ 独立 | thread_local 变量 |

### 线程的最小开销

创建一个线程至少需要：
- **用户态**：`std::thread` 对象约 32~64 字节
- **内核态**：线程内核对象（包括 TCB）
- **栈空间**：默认约 1~8 MB（但只提交使用的部分）

所以频繁创建销毁线程不是免费的——这是"线程池"存在的原因。

## 3. 进程 vs 线程

| 对比维度 | 进程 | 线程 |
|---------|------|------|
| **地址空间** | 独立 | 共享 |
| **创建开销** | 大（复制/继承页表等） | 小（共享地址空间） |
| **上下文切换开销** | 大（TLB 刷新等） | 较小 |
| **通信方式** | IPC：管道、消息队列、共享内存、socket | 直接共享内存 |
| **同步需求** | 少（地址隔离） | 多（共享数据需要锁） |
| **崩溃影响** | 一个进程崩溃不影响其他进程 | 线程崩溃通常导致整个进程崩溃 |
| **安全性** | 高（隔离好） | 低（共享多） |

一句概括：**进程是资源容器，线程是执行单元。**

## 4. 为什么需要多线程？

### 原因 1：利用多核 CPU

```
单核时代：程序快 = 时钟频率高
  1 GHz → 2 GHz → 4 GHz（物理极限）

多核时代：程序快 = 并行度
  ┌─────┬─────┬─────┬─────┐
  │ 核 0 │ 核 1 │ 核 2 │ 核 3 │
  ├─────┼─────┼─────┼─────┤
  │ 线程1│ 线程2│ 线程3│ 线程4│
  └─────┴─────┴─────┴─────┘
```

如果程序只用一个线程，最多只用一个核。4 核 CPU 上约 75% 的算力被浪费。

### 原因 2：避免阻塞 → 提高响应性

```cpp
// ❌ 单线程：点击按钮 → 网络请求 → 卡住 2 秒 → 恢复
void on_button_click() {
    auto data = fetch_from_network();  // 阻塞 2 秒
    update_ui(data);                   // UI 在这之前一直无响应
}

// ✅ 多线程：后台请求，UI 保持流畅
void on_button_click() {
    std::thread([this] {
        auto data = fetch_from_network();
        update_ui(data);              // 回到主线程更新 UI
    }).detach();
    // UI 线程立即返回，不被阻塞
}
```

### 原因 3：提高吞吐量

服务器场景：每个请求独立处理，多线程能同时处理多个请求。

```
单线程服务器：
请求 A ████████████░░░░  ← 4 秒
请求 B ░░░░████████████  ← 4 秒
请求 C ░░░░░░░░████████  ← 4 秒
总计：12 秒

多线程服务器（3 线程）：
请求 A ████████████
请求 B ████████████
请求 C ████████████
总计：4 秒（假设无锁争用）
```

## 5. 并发的代价：并行带来的问题

多线程不是没有代价的：

```
无同步的共享内存 ← 数据竞争 (data race)
         ↓
    竞态条件 (race condition)
         ↓
    死锁 (deadlock)
         ↓
    活锁 (livelock)
         ↓
    优先级反转 (priority inversion)
```

最小代价的并发：**能不共享就不共享**（比如 thread_local、消息传递）。

## 6. 现代 C++ 中的线程安全理解路径

```
┌──────────────┐
│  认识并发问题  │  ← 数据竞争、竞态条件（本节）
├──────────────┤
│  基础同步工具  │  ← std::thread, std::mutex
├──────────────┤
│  高级同步模式  │  ← 条件变量、atomic、future
├──────────────┤
│  复杂设计模式  │  ← 线程池、读写锁、无锁数据结构
├──────────────┤
│  底层内存模型  │  ← 内存序、原子操作语义
└──────────────┘
```

## 7. 一句话总结

> **线程是让程序"同时"做多件事的手段，而代价是共享数据时必须同步。**
