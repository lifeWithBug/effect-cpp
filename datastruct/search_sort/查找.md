## 一、查找问题概述

**查找** = 从数据集合中找到指定元素的位置或关联值。

| 方法 | 时间复杂度 | 数据要求 | 典型场景 |
|------|-----------|---------|---------|
| 顺序查找 | O(n) | 无 | 小数据、无序数据 |
| 二分查找 | O(log n) | **有序** | 有序数组、内存中查找 |
| 哈希表 | O(1) 平均 | 需哈希函数 | 键值对存储、缓存、去重 |
| BST 查找 | O(log n) 平均 | 可比较 | 动态插入/删除的查找 |

## 二、顺序查找

### 2.1 原理

从头到尾逐个比较，找到了就返回位置，找不到返回 -1。

```c
int seqSearch(int arr[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (arr[i] == key) return i;
    return -1;
}
```

### 2.2 哨兵优化

把 key 放在数组末尾，省掉每次循环的 `i < n` 边界判断。

```c
int seqSearchSentinel(int arr[], int n, int key) {
    arr[n] = key;           /* 放哨兵 */
    int i = 0;
    while (arr[i] != key) i++;
    return (i < n) ? i : -1;
}
```

哨兵版本在数据量大时约快 20-30%（省了一次比较），但需要数组有 n+1 空间。

**适用**：无序数据、小规模数据、链表（仅支持顺序访问）。

### 2.3 复杂度

| | 最好 | 最差 | 平均 |
|--|------|------|------|
| 时间 | O(1) | O(n) | O(n) |
| 空间 | O(1) | O(1) | O(1) |

## 三、二分查找

### 3.1 原理

**前提**：数据**必须有序**。

每次取中间元素比较，比 key 大就往左，小就往右。每次排除一半数据，O(log n) 次后找到。

```c
int binarySearch(int arr[], int n, int key) {
    int left = 0, right = n - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;  // 防溢出！

        if      (arr[mid] == key) return mid;
        else if (arr[mid] >  key) right = mid - 1;
        else                      left  = mid + 1;
    }
    return -1;
}
```

> **关键细节**：`mid = left + (right - left) / 2` 而不是 `(left + right) / 2`。当 left 和 right 都很大时，`left+right` 可能溢出整型范围。教科书上用后者，工程和面试必须用前者。

### 3.2 递归版

```c
int binarySearchRecur(int arr[], int left, int right, int key) {
    if (left > right) return -1;

    int mid = left + (right - left) / 2;

    if      (arr[mid] == key) return mid;
    else if (arr[mid] >  key) return binarySearchRecur(arr, left, mid-1, key);
    else                      return binarySearchRecur(arr, mid+1, right, key);
}
```

递归和迭代都能工作，但迭代版避免了函数调用开销，实际中更常用。

### 3.3 三种常见变体

| 变体 | 作用 | 代码区别 |
|------|------|---------|
| 标准二分 | 找到任一位置返回 | 找到就返回 |
| 第一个等于 | 重复数据中找最左侧 | 找到后 `right = mid - 1` 继续往左 |
| 最后一个等于 | 重复数据中找最右侧 | 找到后 `left = mid + 1` 继续往右 |

**第一个等于的实现：**

```c
int binarySearchFirst(int arr[], int n, int key) {
    int left = 0, right = n - 1, result = -1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == key) {
            result = mid;
            right = mid - 1;    // 继续往左找
        } else if (arr[mid] > key) {
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    return result;
}
```

**最后一个等于的实现：** 同理，找到后 `left = mid + 1` 继续往右找。

### 3.4 复杂度

| | 最好 | 最差 | 平均 |
|--|------|------|------|
| 时间 | O(1) | O(log n) | O(log n) |
| 空间（迭代） | O(1) | O(1) | O(1) |
| 空间（递归） | O(log n) | O(log n) | O(log n) |

n=10 万时最多 17 次比较，n=10 亿时最多 30 次。这速度是顺序查找无法比拟的。

### 3.5 局限性

- **数据必须有序**。每次插入/删除后维护有序的成本可能很高。
- **仅适用于数组**（随机访问）。链表无法二分——即使有序，链表的随机访问是 O(n)。
- **插入/删除成本高**。有序数组中插入一个元素需要 O(n) 时间移动后续元素。

## 四、哈希表

哈希表将查找效率从 O(log n) 进一步提升到平均 **O(1)**。核心思想：通过哈希函数将 key 直接映射为数组下标，一步到位找到数据。

### 4.1 基本概念

```
key → hash(key) → 数组下标 → arr[index] = value
```

| 术语 | 含义 |
|------|------|
| 哈希表（Hash Table） | 通过哈希函数实现快速查找的数据结构 |
| 哈希函数（Hash Function） | 将 key 映射为数组下标的函数 |
| 冲突（Collision） | 不同 key 映射到相同下标 |
| 负载因子（Load Factor） | 已占用 / 总大小，≥ 阈值时需扩容 |
| 再哈希（Rehashing） | 扩容后重新计算所有 key 的位置 |

### 4.2 哈希函数

最简单的哈希函数——除留余数法：

```c
int hash(int key, int tableSize) {
    return abs(key) % tableSize;
}
```

设计原则：
- 计算速度要快
- 分布要均匀
- 同一 key 始终得到同一 hash 值

> **表大小选素数** 能有效减少冲突。例如表大小 10=2×5，如果 key 全是 10 的倍数，所有 key 都冲突到位置 0。

### 4.3 链地址法（Separate Chaining）

每个桶存一个链表，冲突的 key 都挂到链表上。

```c
typedef struct Entry {
    int key;
    int value;
    struct Entry *next;
} Entry;

typedef struct {
    Entry **buckets;   // 指针数组，每个元素是链表头
    int size;
} HashChain;

void putChain(HashChain *h, int key, int val) {
    int idx = hash(key, h->size);
    // 先检查是否已存在
    for (Entry *p = h->buckets[idx]; p; p = p->next)
        if (p->key == key) { p->value = val; return; }
    // 不存在则头插
    Entry *e = (Entry *)malloc(sizeof(Entry));
    e->key = key; e->value = val;
    e->next = h->buckets[idx];
    h->buckets[idx] = e;
}

int getChain(HashChain *h, int key, int *found) {
    int idx = hash(key, h->size);
    for (Entry *p = h->buckets[idx]; p; p = p->next)
        if (p->key == key) { *found = 1; return p->value; }
    *found = 0; return -1;
}
```

**演示**（表大小=10，插入 15, 25, 35, 3, 7）：

```
[3] → (3)
[5] → (15) → (25) → (35)   // 三个 key 冲突在桶 5，按头插顺序排列
[7] → (7)
```

| 操作 | 平均 | 最差 |
|------|------|------|
| 插入 / 查找 / 删除 | O(1) | O(n)（所有 key 冲突到同一桶） |

最差情况解决方案：链表超过阈值（如 8）转红黑树（Java 8 HashMap）。

### 4.4 开放地址法（Open Addressing）

不存链表，冲突后寻找下一个空位。

**线性探测**：`(hash(key) + i) % size`，i = 0, 1, 2, ...

```c
void putOpen(HashOpen *h, int key, int val) {
    int idx = hash(key, h->size);
    int start = idx;
    while (h->used[idx]) {
        if (h->keys[idx] == key) { h->values[idx] = val; return; }
        idx = (idx + 1) % h->size;
        if (idx == start) return;  // 表满了
    }
    h->keys[idx] = key;
    h->values[idx] = val;
    h->used[idx] = 1;
    h->count++;
}
```

**演示**（表大小=10，插入 15, 25, 35, 7, 3）：

```
插入 15 → idx=5 (空)        → 放 [5]
插入 25 → idx=5 (满)→ idx=6 (空) → 放 [6]
插入 35 → idx=5,6(满)→ idx=7 (空) → 放 [7]
插入  7 → idx=7 (满)→ idx=8 (空) → 放 [8]
插入  3 → idx=3 (空)        → 放 [3]
```

| 优点 | 缺点 |
|------|------|
| 无需额外指针空间 | 删除麻烦（不能直接清空，需用 DELETED 标记） |
| 数据连续，缓存友好 | 负载因子必须 < 1，建议 < 0.5 |
| 实现简单 | 线性探测有"聚集"问题 |

**二次探测**：`(hash(key) + i²) % size` 可以减轻聚集，但可能查不完所有槽。

### 4.5 负载因子与扩容

**负载因子 α = count / size**

| 方法 | 建议 α 阈值 |
|------|------------|
| 链地址法 | ≤ 0.75 |
| 开放地址法 | ≤ 0.5 |

超过阈值时 **rehashing**：

```
rehash():
    1. 创建新表（大小 ≈ 2 × 旧表）
    2. 遍历旧表，重新计算每个 key 在新表中的位置
    3. 释放旧表
```

均摊复杂度仍然 O(1)——每次插入触发 rehash 的概率越来越低。

### 4.6 链地址法 vs 开放地址法

| | 链地址法 | 开放地址法 |
|--|---------|-----------|
| 冲突解决 | 链表扩展 | 找下一个空位 |
| 空间 | 需额外指针 | 无指针，但需更大表 |
| 负载因子 | 可 > 1 | 必须 < 1 |
| 删除 | 直接删除结点 | 需要"已删除"标记 |
| 缓存 | 链表分散，不友好 | 连续内存，友好 |
| 工程实现 | Java HashMap、C++ unordered_map | Python dict（二次探测） |

## 五、查找算法对比总表

| 算法 | 时间复杂度 | 空间 | 数据要求 | 适用场景 |
|------|-----------|------|---------|---------|
| 顺序查找 | O(n) | O(1) | 无 | 小数据、无序、链表 |
| 二分查找 | O(log n) | O(1) 迭代 | **有序** | 有序数组、静态数据 |
| 二分（递归） | O(log n) | O(log n) | **有序** | 同上（教学用） |
| 哈希表（链地址） | O(1) 平均 | O(n+e) | 可哈希 | 键值对、缓存、去重 |
| 哈希表（开放地址） | O(1) 平均 | O(n) | 可哈希 | 内存敏感、小数据 |
| BST 查找 | O(log n) 平均 | O(n) | 可比较 | 动态插入/删除 |

**选择思路：**

```
需要有序输出？         → BST 或排序后二分
只有插入没有查找？     → 顺序查找够用
静态数据且有序？       → 二分查找
动态插入/删除且查找频繁？→ 哈希表（或 BST 如果有序输出）
极致性能？             → 哈希表
内存受限？             → 开放地址法
```
