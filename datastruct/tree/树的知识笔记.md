## 树 —— 数据结构笔记

### 一、为什么需要树

在此之前我们学的都是 **线性结构**：数组、链表、栈、队列。它们的特点是每个元素最多有一个前驱和一个后继，适合处理"一对一"的关系。

但现实中的很多关系是 **一对多** 的：

- 文件系统：一个文件夹下面有多个子文件夹和文件
- 公司组织架构：CEO 下面有 CTO、CFO，CTO 下面又有多个技术总监
- 一本书的目录：章下面有节，节下面有小节

**树** 就是用来刻画这种 **层次关系** 的数据结构。

---

### 二、核心术语

```
        A          ← 根结点（Root）
      / | \
     B  C  D      ← A 的孩子；B、C、D 互为兄弟（Sibling）
       / \
      E   F       ← 叶子结点（Leaf）：没有孩子的结点
```

| 术语 | 含义 | 一句话解释 |
|------|------|-----------|
| **结点（Node）** | 树中的每个元素 | 图中的每个圆圈 |
| **根结点（Root）** | 没有父结点的那个结点 | 树的起点，一棵树有且只有一个根 |
| **叶子结点（Leaf）** | 没有孩子结点的结点 | 树枝最末端的结点 |
| **父结点 / 子结点（Parent / Child）** | 有直接上下级关系的两个结点 | A 是 B 的父，B 是 A 的子 |
| **兄弟结点（Sibling）** | 同一个父结点的孩子们 | B、C、D 互为兄弟 |
| **边（Edge）** | 结点之间的连线 | 有 n 个结点就有 n-1 条边 |
| **路径（Path**） | 从一个结点走到另一个经过的结点序列 | A → C → F 就是一条路径 |
| **结点的度（Degree）** | 一个结点有几个孩子 | 叶子结点的度为 0 |
| **树的度** | 树中所有结点度的最大值 | 决定了这是"几叉树" |
| **层（Level）** | 根在第 1 层，孩子在第 2 层，… | 从上往下数 |
| **深度（Depth）** | 从根到该结点的边数 | 根深度为 0（有些教材定义为 1） |
| **高度（Height）** | 从该结点到最远叶子的边数 | 叶子高度为 0；树的高度 = 根的高度 |
| **子树（Subtree）** | 任一结点连同它的所有后代 | 子树本身也是一棵树 |

> 计算机里的树是 **根在上、叶子在下** 画的，和自然界倒过来。

---

### 三、树的递归定义（灵魂）

树是一种 **递归** 的数据结构：

> 一棵树由 **一个根结点** 和 **若干棵互不相交的子树** 组成，而这些子树本身也是树。

这就是为什么绝大多数树上的算法都写成递归——不是巧合，是结构本身决定的。

### 四、一般树的性质

**性质 1：n 个结点的树，恰好有 n - 1 条边**

原因很简单：除了根结点，每个结点都有一条来自父结点的"入边"。n 个结点里只有根没有入边，所以共 n-1 条边。

**性质 2：n = 1 + 所有结点的度之和**

和性质 1 是同一回事，但用"度"来表达。每条边贡献了父结点的一度，所以所有度之和 = 边数 = n - 1，移项即得。

**性质 3：任意两个结点之间有且仅有一条简单路径**

因为树没有环。如果能找到两条不同路径，把它们拼起来就构成了一个环——那就不是树了。

**性质 4：度为 m 的树，第 i 层最多有 m^(i-1) 个结点**

第 1 层最多 1 个（= m^0），第 2 层最多 m 个（= m^1），第 3 层最多 m^2 个……每一层翻 m 倍。

**性质 5：高度为 h 的 m 叉树，最多有 (m^h - 1) / (m - 1) 个结点**

把性质 4 每一层的上限加起来（等比数列求和）就是总上限。对二叉树（m=2）：最多 2^h - 1 个结点。

**性质 6：n 个结点的 m 叉树，最小高度为 ⌈ log_m( n(m-1) + 1 ) ⌉**

性质 5 的逆推：给定结点数，树最矮能有多矮。这是平衡树的理论基础。对二叉树：h_min = ⌈ log_2(n+1) ⌉。

**性质 7：树的三个等价定义（满足任一条即是树）**

1. 连通且无环
2. 连通，且边数 = n - 1
3. 无环，且边数 = n - 1

外加两条极值性质：

- 删任意一条边 → 不再连通（树是 **极小连通图**）
- 加任意一条边 → 必然产生环（树是 **极大无环图**）

### 五、二叉树

#### 5.1 定义

每个结点 **最多** 有两个孩子，分别叫 **左孩子** 和 **右孩子**。注意：哪怕只有一个孩子，也必须区分"是左孩子还是右孩子"——这是二叉树和一般度为 2 的树的本质区别。

#### 5.2 二叉树的五种基本形态

1. 空树
2. 只有一个根结点
3. 只有左子树
4. 只有右子树
5. 左右子树都有

#### 5.3 两种特殊的二叉树

**满二叉树**：每一层都"塞满"结点。高度为 h 的满二叉树恰好有 2^h - 1 个结点。

**完全二叉树**：结点按从上到下、从左到右的顺序紧密排列。除了最后一层，其余层全满；最后一层的结点从左到右不间断。

> 满二叉树一定是完全二叉树，反过来不成立。

#### 5.4 二叉树的性质

**性质 8：第 i 层最多有 2^(i-1) 个结点**

一般树性质 4 的 m=2 特例。

**性质 9：深度为 k 的二叉树最多有 2^k - 1 个结点**

一般树性质 5 的 m=2 特例。注意这里 k 是深度（根深度=1）。

**性质 10：n₀ = n₂ + 1（叶子数 = 度为 2 的结点数 + 1）**

推导思路：同时用"边数 = n-1" 和 "边数 = n₁ + 2n₂" 列等式，消去 n 即得。

这是一条只属于二叉树的性质，选择题常考。

**性质 11：链式存储中，空指针域共有 n + 1 个**

每个结点有 left 和 right 两个指针域，共 2n 个。其中 n-1 个指向非根结点，剩下的全是空指针：

```
2n - (n - 1) = n + 1
```

这 n+1 个空指针恰好是 **线索二叉树** 可以利用的空间。

### 六、完全二叉树

#### 6.1 为什么专门研究它

完全二叉树是最"紧凑"的二叉树——结点从根开始，一层一层、从左到右排满。这个排列方式恰好和数组下标完美对应，所以可以用数组来存，省掉指针开销。**堆（Heap）** 就是完全二叉树的经典应用。

#### 6.2 完全二叉树的性质

**性质 12：n 个结点的完全二叉树，深度 = ⌊ log₂ n ⌋ + 1**

由性质 9 的不等式 2^(k-1) - 1 < n ≤ 2^k - 1 取对数推出。考试给结点数直接套公式算深度。

**性质 13：数组存储时的父子下标关系**

设根结点放在下标 1（有些实现从 0 开始，公式略不同）：

| 要找的 | 下标 | 条件 |
|--------|------|------|
| 结点 i 的父结点 | ⌊ i/2 ⌋ | i > 1 |
| 结点 i 的左孩子 | 2i | 2i ≤ n |
| 结点 i 的右孩子 | 2i + 1 | 2i + 1 ≤ n |

如果根从下标 0 开始，则左孩子 = 2i+1，右孩子 = 2i+2，父结点 = ⌊ (i-1)/2 ⌋。

**性质 14：已知结点数 n，可以推出 n₀、n₁、n₂**

完全二叉树中，度为 1 的结点只能是 0 个或 1 个（最后一层从左到右排列，不会出现"左边空、右边有孩子"的情况）。结合 n₀ = n₂ + 1：

| 情况 | n 为奇数 | n 为偶数 |
|------|---------|---------|
| n₀（叶子数） | (n+1)/2 | n/2 |
| n₁（一度结点） | 0 | 1 |
| n₂（二度结点） | (n-1)/2 | n/2 - 1 |

简化记忆：n₀ = ⌈ n/2 ⌉，n₁ = n % 2 == 0 ? 1 : 0，n₂ = ⌊ n/2 ⌋ - 1。

### 七、森林（Forest）

m 棵互不相交的树的集合叫 **森林**。

关键转换关系：

- 给森林加一个根结点，把所有树的根连上去 → 变成一棵树
- 删掉一棵树的根结点 → 变成一片森林（原来的子树们）

树和森林的遍历也因此有对应关系，后续学 **树与二叉树的转换** 时会用到。

### 八、树的遍历

#### 8.1 深度优先遍历（DFS）—— 对二叉树

按"访问根的时机"分为三种：

| 方式 | 顺序 | 形象记忆 |
|------|------|---------|
| 前序（Pre-order） | 根 → 左子树 → 右子树 | 一到结点就先访问 |
| 中序（In-order） | 左子树 → 根 → 右子树 | 从左回来再访问根 |
| 后序（Post-order） | 左子树 → 右子树 → 根 | 左右都走完才访问根 |

对于 **二叉搜索树（BST）**，中序遍历得到的是 **升序序列**。

#### 8.2 广度优先遍历（BFS）—— 层序遍历

从上到下，每层从左到右，用队列实现。

#### 8.3 树和森林的遍历对应关系

| 树的遍历 | 对应的二叉树遍历 |
|----------|-----------------|
| 先根遍历 | 前序遍历 |
| 后根遍历 | 中序遍历 |

| 森林的遍历 | 对应的二叉树遍历 |
|------------|-----------------|
| 先序遍历森林 | 前序遍历 |
| 中序遍历森林 | 中序遍历 |

### 九、树的存储方式

#### 9.1 双亲表示法（Parent Representation）

用一个数组存每个结点，额外记录其父结点下标。适合"向上找父亲"频繁的场景，比如并查集。

#### 9.2 孩子表示法（Child Representation）

每个结点维护一个孩子链表。适合"向下找孩子"。

#### 9.3 孩子兄弟表示法（Child-Sibling） / 二叉链表

每个结点存两个指针：**第一个孩子** 和 **下一个兄弟**。这是 **树转二叉树** 的标准方式——任何一棵树都能用这种方法转成二叉树。

#### 9.4 二叉树的链式存储（最常用）

```c
struct TreeNode {
    int data;
    struct TreeNode *left;   // 左孩子
    struct TreeNode *right;  // 右孩子
};
```

#### 9.5 数组存储（仅适用于完全二叉树）

利用性质 13 的下标关系，直接把结点按层序放在数组里，省掉指针。

### 十一、知识地图

```
树
├── 一般树（任意孩子数）
├── 二叉树（最多两个孩子）
│   ├── 满二叉树（每层全满）
│   ├── 完全二叉树（紧凑排列，可用于堆）
│   ├── 二叉搜索树 BST（左 < 根 < 右）
│   ├── 平衡二叉树 AVL（高度差 ≤ 1）
│   ├── 红黑树（近似平衡，C++ map / Java TreeMap）
│   ├── 哈夫曼树（最优二叉树，用于数据压缩）
│   └── 线索二叉树（利用空指针加速遍历）
├── 堆（最大堆 / 最小堆，用完全二叉树实现）
├── B 树 / B+ 树（数据库索引核心）
└── 森林（多棵树的集合）
```
