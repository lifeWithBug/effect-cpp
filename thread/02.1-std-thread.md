# C++ 多线程笔记 02.1：线程生命周期与常见陷阱

## 1. join 与 detach

`std::thread` 创建后，必须选择**join**或者**detach**，否则析构时会调用 `std::terminate()`。

### join()——等待线程结束

```cpp
#include <iostream>
#include <thread>

void work() {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "Work done\n";
}

int main() {
    std::thread t(work);
    t.join();          // 阻塞直到 t 结束
    // t.joinable() 此时返回 false
    return 0;
}
```

- 调用 `join()` 后，当前线程**阻塞**直到目标线程执行完毕
- `join()` 只能调用一次，重复调用会抛 `std::system_error`
- 必须先检查 `joinable()` 再 join，否则抛异常

### detach()——分离线程到后台

```cpp
std::thread t([]{
    std::this_thread::sleep_for(std::chrono::seconds(2));
    std::cout << "Background work done\n";
});
t.detach();   // 线程分离到后台，继续执行
// t.joinable() 返回 false，不再能 join

// 主线程继续执行，不会等后台线程
std::cout << "Main continues\n";
```

- detach 后线程在后台独立运行，C++ 运行时在**线程退出时自动回收资源**（栈、寄存器等）
- 不能再 `join()` 或 `detach()`，调用会抛异常
- 分离线程的生命周期最长可到进程结束——如果 main 结束了而线程还在跑，线程会被强行终止

### join vs detach 对比

| | join | detach |
|------|------|--------|
| **行为** | 等待线程结束 | 分离到后台 |
| **当前线程是否阻塞** | 是，直到线程完成 | 否，立即返回 |
| **线程资源回收** | join 返回后自动回收 | 线程退出时自动回收 |
| **能否获取结果** | 可以（通过引用参数） | 比较困难 |
| **适用场景** | 需要等待计算结果 | 后台任务、fire-and-forget |
| **重复调用** | 抛异常 | 抛异常 |
| **析构时未处理** | std::terminate() | std::terminate() |

### 用 RAII 包装防止忘记 join

忘记 join/detach 是新手最容易犯的错误，一个简单的 RAII 包装可以保证不会漏：

```cpp
class ThreadGuard {
    std::thread& t_;
public:
    explicit ThreadGuard(std::thread& t) : t_(t) {}

    ~ThreadGuard() {
        if (t_.joinable()) {
            t_.join();  // 析构时自动 join
        }
    }

    // 禁止拷贝和赋值
    ThreadGuard(const ThreadGuard&) = delete;
    ThreadGuard& operator=(const ThreadGuard&) = delete;
};

void process() {
    std::thread t([]{ /* 一些工作 */ });
    ThreadGuard guard(t);  // 离开作用域时自动 join

    // 中间代码即使抛异常，guard 的析构也会执行 join
    // do_something_that_may_throw();

    // 不需要显式 t.join()
}  // guard 析构 → t.join()
```

更简洁的 C++ 替代方案：用 scope_exit 或直接写 lambda 包裹。

## 2. 常见陷阱

### 陷阱 1：析构时未 join/detach → std::terminate

```cpp
// ❌ 错误：thread 对象析构时线程还在运行
{
    std::thread t([]{ /* 工作 */ });
    // 忘记 join，也忘记 detach
}  // t 析构 → 检查发现 joinable() == true → 程序终止！
```

**规则**：`std::thread` 析构时如果 `joinable() == true`，会调用 `std::terminate()` 直接结束进程。这不是抛异常——catch 不住。

```cpp
// ✅ 正确：三种处理方式
{
    std::thread t(work);
    t.join();                     // 方式1：等它结束
}

{
    std::thread t(work);
    t.detach();                   // 方式2：放手
}

{
    std::thread t(work);
    ThreadGuard g(t);             // 方式3：RAII 自动 join
}
```

### 陷阱 2：detach 后访问已销毁的局部变量

```cpp
// ❌ 错误：线程还在跑，但变量已经没了
int main() {
    int data = 42;
    std::thread t([&data] {           // 引用捕获局部变量
        std::this_thread::sleep_for(std::chrono::seconds(1));
        std::cout << data;            // data 可能已经销毁了！
    });
    t.detach();
    return 0;                         // data 被销毁
}  // 线程可能还在后台执行
```

```cpp
// ✅ 正确做法：拷贝数据（按值捕获）
int main() {
    int data = 42;
    std::thread t([data] {            // ✅ 按值捕获，拷贝一份
        std::this_thread::sleep_for(std::chrono::seconds(1));
        std::cout << data;            // 安全的
    });
    t.detach();
    return 0;
}
```

**原则**：detach 的线程里，只能访问以下变量：
- 按值捕获/传递的拷贝
- 静态/全局变量（生命周期贯穿整个进程）
- 堆上分配且有引用计数的对象（如 `shared_ptr`）

### 陷阱 3：传参时隐式转换导致编译失败

```cpp
void process_data(std::string& data) {
    data += " processed";
}

int main() {
    char buf[] = "hello";

    // ❌ 错误：char* 被 std::thread 内部转换为右值 std::string
    // 右值无法绑定到 std::string& 参数
    // std::thread t(process_data, buf);

    // ✅ 正确：用 std::ref 显式包装
    std::thread t(process_data, std::ref(buf));
    t.join();
    std::cout << buf << "\n";        // "hello processed"
    return 0;
}
```

**本质原因**：`std::thread` 构造函数会将所有参数**按值 decay-copy** 到内部存储，再转发给目标函数。如果目标函数要引用参数，必须用 `std::ref` 包装。

### 陷阱 4：移动构造后的 thread 不再代表原线程

```cpp
std::thread t1(worker);
std::thread t2 = std::move(t1);   // t1 不再代表任何线程

// ❌ 错误：t1 不再 joinable
// t1.join();   // 抛异常

// ✅ 正确：t2 拥有线程
t2.join();
```

`std::thread` 是 move-only 类型（不可复制）。移动后原对象 `joinable()` 返回 false。

## 3. 其他实用 API

```cpp
// 获取硬件支持的并发线程数（逻辑核心数）
unsigned int n = std::thread::hardware_concurrency();
// 可能是 0（无法检测），通常等于 CPU 核心数

// 当前线程 ID
std::thread::id tid = std::this_thread::get_id();
// 可以输出、比较、作为 map key

// 休眠
using namespace std::chrono_literals;
std::this_thread::sleep_for(100ms);          // 休眠 100 毫秒
std::this_thread::sleep_until(now + 2s);     // 休眠到某个时间点

// 让出 CPU 时间片
std::this_thread::yield();                   // 提示调度器：我可以让出 CPU
```

## 4. 配置线程属性（平台相关）

C++ 标准库没有提供跨平台设置线程属性的接口，需要直接使用平台 API。

### 设置线程名（Windows）

```cpp
#include <windows.h>

void set_thread_name(const std::string& name) {
    // Windows 10 1607+：推荐方式
    SetThreadDescription(GetCurrentThread(),
        std::wstring(name.begin(), name.end()).c_str());
}

std::thread t([&] {
    set_thread_name("Worker-1");
    // 在调试器中可以看到线程名
});
```

设置线程名在调试多线程程序时非常有用——调试器的线程列表会显示有意义的名称。

### 设置线程栈大小（Windows）

```cpp
// C++ 的 std::thread 不提供设置栈大小的接口
// Windows 下需要用 _beginthreadex
#include <process.h>

unsigned int __stdcall thread_func(void*) {
    // 工作代码
    return 0;
}

// 设置 1MB 栈
HANDLE h = (HANDLE)_beginthreadex(
    nullptr,           // 安全属性
    1 << 20,           // 栈大小 1MB
    thread_func,
    nullptr,           // 参数
    0,                 // 创建标志
    nullptr            // 线程 ID
);
WaitForSingleObject(h, INFINITE);
CloseHandle(h);
```

默认线程栈通常是 1MB（Windows）或 8MB（Linux）。大部分场景不需要调整，除非栈上分配了大数组或深度递归。
