# C++ 多线程问题笔记

# 1. sleep vs wait 对比笔记

## 一、核心区别

> **`sleep`**：线程自己暂停，不释放锁，时间到自动醒。
> **`wait`**：线程等待条件，释放锁，靠别人通知（或虚假唤醒）醒来。

| 特性 | `sleep` | `wait` |
|------|---------|--------|
| **所属** | `std::this_thread::sleep_for/sleep_until` | `std::condition_variable::wait` |
| **目的** | 单纯延时 | 等待某个条件成立 |
| **是否释放锁** | **不释放**（如果持有锁会死锁） | **必须释放**（调用时原子性释放锁并阻塞） |
| **唤醒条件** | 时间到自动醒 | `notify_one/notify_all` 或 虚假唤醒 |
| **需要配合锁** | 不需要 | **必须**配合 `std::unique_lock` |
| **适用场景** | 定时任务、轮询、模拟耗时 | 生产者-消费者、线程间同步等待 |

---

## 二、典型代码

### 1. sleep — 单纯延时

```cpp
#include <thread>
#include <chrono>

// 当前线程休眠 100 毫秒，无论其他线程在做什么
std::this_thread::sleep_for(std::chrono::milliseconds(100));
```
### 2. wait - 等待
```cpp
#include <mutex>
#include <condition_variable>

std::mutex mtx;
std::condition_variable cv;
bool ready = false;  // 条件变量

// ========== 等待方 ==========
void wait_thread() {
    std::unique_lock<std::mutex> lock(mtx);
    
    // 带谓词的 wait：自动处理虚假唤醒
    cv.wait(lock, []{ return ready; });
    
    // 被唤醒后已自动持有锁，继续执行...
}

// ========== 通知方 ==========
void notify_thread() {
    {
        std::lock_guard<std::mutex> lock(mtx);
        ready = true;
    }
    cv.notify_one();  // 唤醒一个等待线程
    // 或 cv.notify_all(); // 唤醒所有等待线程
}
```

# 2.什么时候使用pthread_mutex_init(...)


|变量类型	|初始化方式|	是否需要 _init|	是否需要 _destroy|
|------|---------|--------|--------|
|全局变量（默认属性）|	PTHREAD_MUTEX_INITIALIZER	|❌ 不需要	|❌ 不需要（但调用无害）|
|静态局部变量（默认属性）	|PTHREAD_MUTEX_INITIALIZER|	❌ 不需要	|❌ 不需要（但调用无害）|
|堆分配变量	|pthread_mutex_init(...)	|✅ 必须	|✅ 必须|
|栈分配变量|	pthread_mutex_init(...)	|✅ 必须	|✅ 必须|
|需要自定义属性|	pthread_mutex_init(&mutex, &attr)	|✅ 必须	|✅ 必须|
