## 一、二叉搜索树 BST

### 1.1 定义

一棵二叉树，对任意结点满足：

> **左子树所有值 < 结点值 < 右子树所有值**

中序遍历 BST 得到升序序列——这是它名字的由来，也是所有操作的基础。

### 1.2 查找（Search）

```
在 BST 中找值 x：
  如果 x == 根 → 找到
  如果 x < 根  → 去左子树找
  如果 x > 根  → 去右子树找
```

递归或 while 循环皆可。时间复杂度 O(h)，其中 h 为树高。

### 1.3 插入（Insert）

```
在 BST 中插入值 x：
  从根出发，沿查找路径一直走到找不到为止
  将 x 插在最后位置（一定是叶子）
```

插入不会改变已有结点的结构，新结点永远是叶子。

### 1.4 删除（Delete）—— 三种情况

删除是 BST 里唯一有"技术含量"的操作。设待删结点为 p：

| 情况 | 操作 | 复杂度 |
|------|------|--------|
| ① p 是叶子 | 直接删 | 简单 |
| ② p 只有一个孩子 | 用孩子替换 p | 简单 |
| ③ p 有两个孩子 | 找 p 的 **中序后继**（右子树最左下），将它的值覆盖到 p，再删除那个后继（它至多有一个右孩子，退化为情况①或②） | 需理解 |

**为什么找中序后继？** BST 的中序序列是有序的，p 的后继恰好是"比 p 大且最近的结点"。用它替换 p，BST 性质不会破坏。

> 同理也可找"中序前驱"（左子树最右下）。

### 1.5 BST 的问题

如果按升序插入 [1, 2, 3, 4, 5]，树退化成一条链，高度 h = n，查找变成 O(n)。这就是下一节 AVL 要解决的问题。

## 二、平衡二叉树 AVL

### 2.1 定义

> 一棵 BST，且对任意结点，**| 左子树高度 - 右子树高度 | ≤ 1**

这个差值叫 **平衡因子（Balance Factor, BF）**。AVL 规定 BF 只能取 -1、0、1。

### 2.2 失衡与旋转

插入新结点后从下往上回溯，第一个出现 |BF| = 2 的结点需要旋转。四种情况：

| 情况 | BF(根) | 子结点 BF | 旋转方式 |
|------|--------|----------|---------|
| LL | +2 | 左孩子 BF ≥ 0 | 右旋（一次） |
| RR | -2 | 右孩子 BF ≤ 0 | 左旋（一次） |
| LR | +2 | 左孩子 BF ≤ -1 | 左旋左孩子 + 右旋根 |
| RL | -2 | 右孩子 BF ≥ 1 | 右旋右孩子 + 左旋根 |

命名规则：`L` = 左边重，`R` = 右边重。`LR` = 整体左边重，但左孩子的右边更重。

**LL 型 → 右旋**（图示）：

```
     root(2)           newRoot
     /    \             /    \
    A(1)   C    -->    B    root
   /   \                    /   \
  B     D                  D     C
```

**RR 型 → 左旋**（与右旋完全对称）。

**LR 型 → 左右双旋**：先对左子树左旋（变成 LL 型），再对根右旋。

**RL 型 → 右左双旋**：先对右子树右旋（变成 RR 型），再对根左旋。

### 2.3 插入算法

```
insert(root, x):
    1. 普通 BST 插入
    2. 回溯：更新高度
    3. 计算平衡因子
    4. 如果 |BF| = 2：
       根据 x 落在子结点的哪一侧，判断旋转类型并执行
    5. 返回新的子树根
```

### 2.4 删除（简述）

删除比插入复杂——可能沿路径向上连锁失衡，需要反复旋转修复。思路：普通 BST 删除 + 回溯修复 BF，直到根。

### 2.5 AVL 的定位

严格平衡 → 查找快（O(log n)）、旋转多。工程中红黑树更常用（近似平衡，旋转更少）。但 AVL 是所有平衡树的思想起点。

## 三、线索二叉树

### 3.1 动机

回顾二叉树性质 11：n 个结点有 **n+1 个空指针域**。这些空指针白白浪费。线索二叉树把它们重新利用，指向遍历序列中的 **前驱** 和 **后继**。

### 3.2 结点结构

```c
typedef struct ThreadNode {
    int data;
    struct ThreadNode *left, *right;
    int ltag;  // 0: left 指向左孩子    1: left 指向前驱
    int rtag;  // 0: right 指向右孩子   1: right 指向后继
} ThreadNode;
```

### 3.3 中序线索化

在中序遍历的 visit 环节，利用 `pre` 指针（上一个被访问的结点）：

```
如果 cur 没有左孩子 → cur->left = pre（前驱线索）
如果 pre 没有右孩子 → pre->right = cur（后继线索）
pre = cur
```

一趟中序遍历即可完成全部线索化。

### 3.4 不用栈的遍历 —— 最大优势

**找中序后继（nextNode）：**

```
如果 rtag == 1：right 直接就是后继（线索直通车）
如果 rtag == 0：right 是右孩子 → 后继 = 右子树的最左下结点
```

**找中序前驱（prevNode）：** 对称。

**遍历：**

```c
for (p = firstNode(root); p != NULL; p = nextNode(p))
    printf("%d ", p->data);
```

时间复杂度 O(n)，空间复杂度 O(1)。普通二叉树需要 O(h) 栈。

### 3.5 关键注意事项

线索化后 left/right 可能指向遍历序列中的结点而非子树。**递归遍历必须检查 ltag/rtag，只沿 tag=0 方向走**，否则沿线索绕回已访问结点会死循环。

## 四、哈夫曼树

### 4.1 定义

**带权路径长度（WPL）** = 每个叶子结点权值 × 路径长度的总和。

**哈夫曼树（最优二叉树）** = 给定 n 个权值，WPL 最小的二叉树。

### 4.2 应用场景

假设 6 个字符出现频率不同：

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| 45 | 13 | 12 | 16 | 9 | 5 |

定长编码 3 bit/字符 → 总长 300 bit。哈夫曼编码 → 224 bit，节省 25%。

### 4.3 构建：反复取最小

```
1. 把 n 个权值各自作为一棵单结点树，放入森林
2. 重复 n-1 次：
     选两个权值最小的树合并，产生新结点（权值 = 两者之和）
     新树放回森林
3. 森林只剩一棵树 → 哈夫曼树完成
```

**例**：5 + 9 = 14 → 12 + 13 = 25 → 14 + 16 = 30 → 25 + 30 = 55 → 45 + 55 = 100

左分支标 0，右分支标 1，从根到叶子的路径就是字符的哈夫曼编码：

| 字符 | 编码 | 长度 |
|------|------|------|
| A(45) | 0 | 1 |
| B(13) | 101 | 3 |
| C(12) | 100 | 3 |
| D(16) | 111 | 3 |
| E(9) | 1101 | 4 |
| F(5) | 1100 | 4 |

### 4.4 三个核心性质

**前缀编码**：没有任何一个编码是另一个的前缀。保证解码唯一确定。

**WPL 最小**：由贪心选择性质和最优子结构性质保证（数学推导略）。

**哈夫曼树只有度 0 和度 2 的结点**：总结点数 = 2n-1（n 个叶子 + n-1 个内部结点）。

### 4.5 WPL 的两种计算方式

1. 定义：∑ 叶子权值 × 路径长度
2. 快捷：∑ 所有内部结点（非叶子）的权值。因为每次合并的两个权值之和，恰好等于这两个子树对 WPL 的贡献。

### 4.6 解码

从根出发，读 0 向左走，读 1 向右走，到叶子就输出字符，然后回到根继续。

### 4.7 应用

ZIP/GZip/PNG（Deflate）、JPEG/MP3 熵编码、HTTP/2 HPACK 头部压缩。

## 五、树与二叉树的转换

### 5.1 动机

二叉树结构简单、适合编码。但现实中的数据往往是多叉的（文件夹可有多个子节点）。**孩子兄弟表示法** 提供了统一的方式，把任意树变成二叉树。

### 5.2 转换规则（树 → 二叉树）

```
每棵树的每个结点只存两个指针：
  ① left：指向第一个孩子
  ② right：指向下一个兄弟
```

**步骤：**
1. 所有兄弟之间用横线连起来
2. 每个结点只保留它和第一个孩子的连线，删除和其他孩子的连线
3. 顺时针旋转 45 度（使兄弟关系变成斜线）

转换结果：
```
原树：                  转换后的二叉树：
    A                   A
   /|\                 /
  B C D        →      B
                        \
                         C
                          \
                           D
```

### 5.3 二叉树 → 树（逆转换）

逆操作：二叉树中 left 指向孩子，right 指向兄弟。沿着 right 链的所有结点都是兄弟。

## 六、树和森林的遍历

### 6.1 树的遍历

| 方式 | 规则 | 对应二叉树 | 类比 |
|------|------|-----------|------|
| 先根遍历 | 先访问根，再依次遍历每棵子树 | 前序遍历 | DFS（根先处理） |
| 后根遍历 | 先依次遍历每棵子树，再访问根 | **中序遍历** | 二叉树中序 = 树的后根 |

**关键对应**：树转成二叉树后，树的先根 ⇔ 二叉树的前序，树的后根 ⇔ 二叉树的中序。这是考试常考的对应关系。

### 6.2 森林的遍历

森林 = m 棵树的集合。转换方式：后一棵树当作前一棵树根的右兄弟。

| 方式 | 规则 | 对应二叉树 |
|------|------|-----------|
| 先序遍历 | 先访问第一棵树的根，再先序第一棵树的子树，再先序遍历剩余森林 | 前序遍历 |
| 中序遍历 | 先中序第一棵树的子树，再访问第一棵树的根，再中序遍历剩余森林 | 中序遍历 |

### 6.3 遍历对应关系总表

| 树/森林 | 对应二叉树 |
|---------|-----------|
| 树的先根遍历 | 二叉树前序遍历 |
| 树的后根遍历 | 二叉树中序遍历 |
| 森林的先序遍历 | 二叉树前序遍历 |
| 森林的中序遍历 | 二叉树中序遍历 |

> 根结点是关键：在树转成的二叉树中，**根结点没有右子树**（因为它没有兄弟）。而森林转成的二叉树中，根结点 **有右子树**（右子树是森林的第二棵树）。
